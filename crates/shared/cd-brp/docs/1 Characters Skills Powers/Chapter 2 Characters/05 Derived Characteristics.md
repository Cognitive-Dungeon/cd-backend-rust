## Производные Характеристики (Derived Characteristics)
Числовые показатели, которые вычисляются на основе базовых характеристик персонажа. 

### Механика / Концепция
Производные характеристики не статичны. Если базовые характеристики (`STR`, `CON`, `SIZ` и т.д.) изменяются из-за травм, магии, болезней или иных факторов, все производные от них показатели **немедленно** пересчитываются для отражения нового значения.

> For example, your character (CON 16, SIZ 14, HP 15) falls victim to a deadly poison, which reduces their CON value to 10. Your character’s maximum hit points immediately drop from 15 (16+14=30, divided to 15) to 12 (10+14=24, divided to 12)... If wounds had already brought your character lower than 12 hit points, they would not take any additional damage, but they are limited to the 12 hit point maximum until their original CON is restored.

### Архитектура Rust
Для программиста это означает, что производные характеристики не должны храниться как независимые мутируемые поля, либо их обновление должно происходить через реактивную систему (геттеры, вычисляющие значение на лету, или функцию-рекалькулятор при любом изменении базы).

```rust
// Реактивный подход: вычисление на лету
impl Character {
    pub fn current_max_hp(&self) -> u16 {
        ((self.stats.con as f32 + self.stats.siz as f32) / 2.0).ceil() as u16
    }
}
```

## Damage Modifier (Модификатор Урона)
Отражает физическое преимущество крупных и сильных существ в бою. Выражается в виде кубиков урона, которые прибавляются или отнимаются от успешной атаки.

### Механика / Концепция
Базируется на сумме `STR` + `SIZ`. Применяется к броскам урона следующим образом:
- **Рукопашный бой и Оружие ближнего боя**: Применяется полный модификатор (как положительный, так и отрицательный).
- **Метательное оружие и Луки**: Если модификатор положительный — он делится на 2 с округлением вверх (`ceil`). Если модификатор отрицательный — он применяется полностью (без деления).
- **Огнестрельное и энергетическое оружие** (самодвижущиеся снаряды): Модификатор урона **не применяется** вообще.

Если итоговый урон (после вычета отрицательного модификатора) становится равен `0` или уходит в минус, удар считается слишком слабым, чтобы нанести вред. Урон засчитывается как `0`.

**Таблица Damage Modifier:**
Диапазон `STR` + `SIZ` преобразуется в модификатор:
- **2–12**: `-1D6`
- **13–16**: `-1D4`
- **17–24**: `None` (0)
- **25–32**: `+1D4`
- **33–40**: `+1D6`
- **41–56**: `+2D6`
- **57–72**: `+3D6`
- **73–88**: `+4D6`
- **89–104**: `+5D6`
- **105–120**: `+6D6`
- **121–136**: `+7D6`
- **137–152**: `+8D6`
- **153–168**: `+9D6`
- **Далее**: Каждые полные `16` очков добавляют `+1D6`.

### Архитектура Rust
```rust
#[derive(Debug, Clone, Copy, PartialEq)]
pub enum WeaponPropulsion {
    Melee,          // Ближний бой
    MusclePropelled,// Метательное/Луки
    SelfPropelled,  // Огнестрел/Энергия
}

#[derive(Debug, Clone, Copy)]
pub enum DiceMod {
    Minus(u8, u8), // (Количество кубов, Грани)
    None,
    Plus(u8, u8),
}

pub fn calculate_damage_modifier(str_val: u8, siz_val: u8) -> DiceMod {
    let total = str_val as u16 + siz_val as u16;
    match total {
        0..=12 => DiceMod::Minus(1, 6),
        13..=16 => DiceMod::Minus(1, 4),
        17..=24 => DiceMod::None,
        25..=32 => DiceMod::Plus(1, 4),
        33..=40 => DiceMod::Plus(1, 6),
        _ => {
            // Для 41 и выше каждый шаг в 16 очков добавляет +1D6
            let base_extra = total - 40;
            let dice_count = 1 + (base_extra as f32 / 16.0).ceil() as u8;
            DiceMod::Plus(dice_count, 6)
        }
    }
}

pub fn apply_damage_modifier_to_weapon(
    base_mod: DiceMod, 
    weapon_type: WeaponPropulsion
) -> DiceMod {
    match weapon_type {
        WeaponPropulsion::Melee => base_mod,
        WeaponPropulsion::SelfPropelled => DiceMod::None,
        WeaponPropulsion::MusclePropelled => match base_mod {
            // Отрицательный остается как есть
            DiceMod::Minus(_, _) => base_mod, 
            DiceMod::None => DiceMod::None,
            // Положительный делится пополам (округление вверх)
            DiceMod::Plus(count, faces) => {
                let halved_count = (count as f32 / 2.0).ceil() as u8;
                DiceMod::Plus(halved_count, faces)
            }
        }
    }
}
```

### Граничные случаи и Критические исходы
Атака не может наносить отрицательный урон. В случае отрицательных кубиков (например, `-1D6`), если на кубике выпадает значение больше, чем базовый урон оружия, итоговый результат приравнивается к `0`.

## Experience Bonus (Бонус Опыта)
Показатель того, насколько быстро персонаж обучается, особенно в стрессовых ситуациях.

### Механика / Концепция
Вычисляется как `INT`, разделенный на `2` с округлением вверх (`ceil`). 
Этот бонус прибавляется к каждому броску проверки опыта (`learning roll`) при попытке улучшить навык или характеристику (детальная механика бросков опыта раскрывается в разделе "Skill Improvement").

### Архитектура Rust
```rust
pub fn calculate_experience_bonus(int_val: u8) -> u8 {
    (int_val as f32 / 2.0).ceil() as u8
}
```

## Hit Points (Очки Здоровья)
Мера способности персонажа переносить физический урон.

### Механика / Концепция
- **Максимум**: Рассчитывается как среднее значение между `CON` и `SIZ` с округлением вверх: `ceil((CON + SIZ) / 2)`.
- **Потеря сознания**: Когда текущие `Hit Points` падают до `2` или ниже (включая `1`), персонаж теряет сознание.
- **Смерть**: Если `Hit Points` достигают `0`, персонаж умирает в конце *следующего* боевого раунда (`Combat Round`).
- **Отрицательные значения**: Персонаж может получить урон, уводящий его `Hit Points` в минус. Отрицательные значения необходимо отслеживать, так как их придется лечить для возвращения к жизни или сознанию.
- **Естественное исцеление**: Восстанавливается `roll(1, d3)` очков за каждую игровую неделю (`game week`). Медицинское вмешательство ускоряет процесс.

### Архитектура Rust
```rust
pub struct Health {
    pub max_hp: u16,
    pub current_hp: i16, // i16 для поддержки отрицательных значений
}

pub enum HealthState {
    Active,
    Unconscious,
    Dying, // Умрет в конце следующего раунда
}

impl Health {
    pub fn state(&self) -> HealthState {
        if self.current_hp <= 0 {
            HealthState::Dying
        } else if self.current_hp <= 2 {
            HealthState::Unconscious
        } else {
            HealthState::Active
        }
    }
}
```

### Граничные случаи и Критические исходы
Смерть не наступает мгновенно при достижении `0` ХП. У союзников есть время до конца *следующего* боевого раунда, чтобы применить первую помощь (`First Aid`) или магию (`Heal`).

## Опциональное правило: Полные Очки Здоровья (Total Hit Points)
Правило для создания более выносливых героев (подходит для pulp-экшена или героического фэнтези).

### Механика / Концепция
Максимальные `Hit Points` равны сумме `CON` + `SIZ` (без деления на 2). 
Это позволяет персонажам переживать гораздо больше ударов, делает тяжелые ранения (`Major Wounds`) редкостью и снижает шанс мгновенной смерти от критических ударов. 

Гейммастер может использовать это правило асимметрично: применять `Total Hit Points` (Сумма) для игроков и важных боссов, а `Average Hit Points` (Сумма/2) для рядовых врагов ("пушечного мяса").

### Архитектура Rust
```rust
pub enum HpCalculationRule {
    Average, // (CON + SIZ) / 2
    Total,   // CON + SIZ
}

pub fn calculate_max_hp(con: u8, siz: u8, rule: HpCalculationRule) -> u16 {
    let sum = con as u16 + siz as u16;
    match rule {
        HpCalculationRule::Total => sum,
        HpCalculationRule::Average => (sum as f32 / 2.0).ceil() as u16,
    }
}
```

## Опциональное правило: Здоровье по Зонам Попадания (Hit Points by Hit Location)
Детализированная система урона, где каждая часть тела имеет свой запас здоровья.

### Механика / Концепция
Очки здоровья распределяются по частям тела на основе общего максимума `Hit Points` персонажа. При расчете используются дроби от общего `Hit Points`, и **каждая дробь округляется вверх (`ceil`)**:
- **Leg** (Нога, каждая отдельно): `1/3` от общих HP.
- **Abdomen** (Живот): `1/3` от общих HP.
- **Chest** (Грудь): `4/10` от общих HP.
- **Arm** (Рука, каждая отдельно): `1/4` от общих HP.
- **Head** (Голова): `1/3` от общих HP.

Из-за округления вверх сумма ХП всех локаций будет превышать общее максимальное здоровье персонажа. 

**Применение урона:**
1. При успешной атаке бросается `D20` для определения задетой зоны.
2. Полученный урон вычитается **одновременно** из здоровья конкретной зоны и из общих `Hit Points` персонажа.
3. Если урон превышает здоровье локации, локация становится бесполезной.
4. Если урон равен или превышает здоровье локации, умноженное на 2 (`>= location HP * 2`), локация раздавлена или отсечена.

> For example, your character has 14 hit points, with 5 hit points in each leg, 5 hit points in the abdomen, 6 hit points in the chest, 4 hit points in each arm, and 5 hit points in their head. Even though their hit points in all locations total 34, your character will die if they suffer a total of 14 hit points of damage.

### Архитектура Rust
```rust
pub struct HitLocations {
    pub right_leg: u16,
    pub left_leg: u16,
    pub abdomen: u16,
    pub chest: u16,
    pub right_arm: u16,
    pub left_arm: u16,
    pub head: u16,
}

pub fn calculate_hit_locations(total_max_hp: u16) -> HitLocations {
    let hp = total_max_hp as f32;
    
    let one_third = (hp / 3.0).ceil() as u16;
    let four_tenths = (hp * 0.4).ceil() as u16;
    let one_fourth = (hp / 4.0).ceil() as u16;

    HitLocations {
        right_leg: one_third,
        left_leg: one_third,
        abdomen: one_third,
        chest: four_tenths,
        right_arm: one_fourth,
        left_arm: one_fourth,
        head: one_third,
    }
}

pub enum LocationStatus {
    Healthy,
    Useless,
    SeveredOrCrushed,
}

pub fn get_location_status(current_damage_taken: u16, location_max_hp: u16) -> LocationStatus {
    if current_damage_taken >= (location_max_hp * 2) {
        LocationStatus::SeveredOrCrushed
    } else if current_damage_taken > location_max_hp {
        LocationStatus::Useless
    } else {
        LocationStatus::Healthy
    }
}
```

### Граничные случаи и Критические исходы
Персонаж может умереть от истощения общего пула `Hit Points`, даже если ни одна локация не была уничтожена. И наоборот, мгновенное уничтожение головы (урон `>= 2x Head HP`) приводит к смерти (детали в правилах боя), несмотря на то, что общий пул `Hit Points` мог еще не опуститься до `0`.

## Power Points (Очки Силы)
Резерв духовной или жизненной энергии персонажа (`PP`), используемый для применения магии, мутаций, псионики или суперспособностей.

### Механика / Концепция
Максимальное базовое количество `Power Points` равно характеристике `POW`. 

**Переполнение (Временные очки):**
В отличие от здоровья или усталости, `Power Points` могут кратковременно превышать максимальное значение (обычно за счет получения энергии извне или способностей). Персонаж может хранить "лишних" очков в количестве до `POW × 2`. Любые очки сверх этого сгорают. 
При использовании способностей временные очки тратятся в первую очередь. Они не восстанавливаются естественным путем и полностью исчезают после ночного сна или по решению `Gamemaster` (Гейммастера). (Предметы-накопители не считаются личным переполнением).

**Падение до нуля:**
При достижении `0` `Power Points` персонаж полностью истощается и падает в обморок, пока не восстановит хотя бы `1` очко. Отрицательных значений не бывает.

**Восстановление (Recovery Rate):**
Очки восстанавливаются в зависимости от активности персонажа (Сон или Бодрствование) и размера его максимального пула. При тяжелых физических нагрузках восстановление не происходит.

*Таблица Power Point Recovery Rate:*
- **Max PP 1–24**: Во сне: 1 в час. Бодрствуя: 1 за 2 часа.
- **Max PP 25–48**: Во сне: 2 в час. Бодрствуя: 1 в час.
- **Max PP 49–72**: Во сне: 3 в час. Бодрствуя: 1 за 40 минут.
- **Max PP 73–96**: Во сне: 4 в час. Бодрствуя: 1 за 30 минут.
- **Max PP 97+**: Во сне: +1 в час. Бодрствуя: время делится пополам.

### Архитектура Rust
```rust
pub struct PowerPoints {
    pub current: u16,
    pub max_base: u16,      // Равно POW
    pub temp_overflow: u16, // Временные очки (лимит POW * 2)
}

impl PowerPoints {
    // Трата очков: сначала списываются временные
    pub fn spend(&mut self, amount: u16) -> Result<(), &'static str> {
        let total_available = self.current + self.temp_overflow;
        if total_available < amount {
            return Err("Not enough Power Points");
        }
        
        if self.temp_overflow >= amount {
            self.temp_overflow -= amount;
        } else {
            let remainder = amount - self.temp_overflow;
            self.temp_overflow = 0;
            self.current -= remainder;
        }
        Ok(())
    }

    // Проверка обморока
    pub fn is_unconscious(&self) -> bool {
        self.current == 0 && self.temp_overflow == 0
    }

    // Сброс переполнения после сна
    pub fn reset_overflow_after_sleep(&mut self) {
        self.temp_overflow = 0;
    }
}
```

### Граничные случаи и Критические исходы
Использование предметов, хранящих ману (например, магических посохов), не влияет на лимит временного переполнения персонажа (`POW × 2`). Очки в предметах хранятся и тратятся изолированно.

## Опциональное правило: Другие названия Очков Силы (Other Kinds of Power Points)
Косметическое изменение терминологии.

### Механика / Концепция
Из-за многообразия систем сил (магия, мутации, псионика) термин "Power Points" является универсальным. Гейммастер может переименовать его в "Magic Points", "Energy Points", "Mana" в зависимости от сеттинга. Рекомендуется использовать одно унифицированное название в рамках одной игры во избежание путаницы.

## Movement / MOV (Движение)
Скорость перемещения персонажа.

### Механика / Концепция
Все люди и гуманоиды по умолчанию имеют атрибут `MOV` равный `10`. `MOV` определяет дистанцию, которую персонаж может преодолеть за один `Combat Round`. 

Дистанция 1 единицы `MOV` гибкая и зависит от темпа:
- **Шаг (Walk)**: 1 метр за 1 `MOV` (10 метров за раунд).
- **Средний темп в бою (Combat)**: 3 метра за 1 `MOV` (30 метров за раунд).
- **Бег (Run)**: до 5 метров за 1 `MOV` (50 метров за раунд).

### Архитектура Rust
```rust
pub struct Movement {
    pub base_mov: u8,
}

impl Movement {
    pub fn distance_walked_per_round(&self) -> u16 {
        self.base_mov as u16 * 1
    }
    
    pub fn distance_combat_per_round(&self) -> u16 {
        self.base_mov as u16 * 3
    }
    
    pub fn distance_run_per_round(&self) -> u16 {
        self.base_mov as u16 * 5
    }
}
```

## Опциональное правило: Fatigue Points (Очки Усталости)
Система детального учета выносливости для отслеживания перегрузок.

### Механика / Концепция
Максимальные `Fatigue Points` (FP) равны сумме характеристик `STR` + `CON`. Базовое значение может снижаться в зависимости от переносимого груза (Encumbrance).

**Трата очков:**
- `1` FP за каждый `Combat Round` тяжелой физической активности (ближний бой, спринт, плавание, лазание).
- `1` FP за каждый `Full Turn` (5 минут) изнурительного труда или спринта вне боя.
- `1` FP за каждый час форсированного марша.

**Последствия истощения:**
Персонаж может действовать при отрицательных значениях FP. 
- Как только `FP` опускается ниже `0`, персонаж получает кумулятивный штраф `-1%` ко всем броскам навыков, характеристик и сопротивления **за каждое отрицательное очко**.
- Когда отрицательное значение `FP` достигает предела базовых `FP` (т.е. `- (STR + CON)`), персонаж полностью выведен из строя (Incapacitated) от истощения. Гейммастер может отправить его в обморок. Даже если персонаж в сознании, он не может совершать никаких действий, пока `FP` не восстановится до положительного значения.

**Восстановление:**
Восстанавливается `1` FP за каждую 1 минуту (5 раундов) отдыха, медленной ходьбы или езды верхом.

### Архитектура Rust
```rust
pub struct FatiguePoints {
    pub current: i16,
    pub max: u16, // STR + CON
}

impl FatiguePoints {
    pub fn penalty_percentage(&self) -> u16 {
        if self.current < 0 {
            self.current.unsigned_abs() // Возвращает процент штрафа (например, 5 для -5)
        } else {
            0
        }
    }

    pub fn is_incapacitated(&self) -> bool {
        self.current <= -(self.max as i16)
    }
}
```

## Опциональное правило: Simple Fatigue (Простая Усталость)
Упрощенная альтернатива очкам усталости, исключающая микроменеджмент очков.

### Механика / Концепция
Вместо счетчика используются фазы утомления, зависящие от количества непрерывных раундов активности и `CON`. Гейммастер может позволить бросок `Stamina`, чтобы отсрочить негативный эффект.
1. **Fatigued (Усталость)**: Наступает после `CON × 3` непрерывных раундов боя/тяжелой работы. **Эффект:** Все проверки навыков становятся `Difficult` (штраф x0.5).
2. **Severe Fatigue (Тяжелая усталость)**: Наступает после `CON × 4` непрерывных раундов. **Эффект:** Навыки падают до `1/4` от их рейтинга. Чтобы совершить любое физическое действие (даже попытаться применить навык), требуется успешный бросок `Stamina`.
3. **Exhaustion (Истощение)**: Наступает после `CON × 10` раундов. Персонаж едва стоит на ногах. **Эффект:** Любое базовое действие требует броска `Stamina` со сложностью `Difficult`. Навыки либо `Impossible`, либо ограничены рейтингом `POW × 1%` (по решению ГМ'а).

### Архитектура Rust
```rust
pub enum SimpleFatigueState {
    Fresh,
    Fatigued,         // CON x 3 rounds
    SevereFatigue,    // CON x 4 rounds
    Exhausted,        // CON x 10 rounds
}

pub fn determine_fatigue_state(con: u8, consecutive_rounds_active: u16) -> SimpleFatigueState {
    let con_u16 = con as u16;
    if consecutive_rounds_active >= con_u16 * 10 {
        SimpleFatigueState::Exhausted
    } else if consecutive_rounds_active >= con_u16 * 4 {
        SimpleFatigueState::SevereFatigue
    } else if consecutive_rounds_active >= con_u16 * 3 {
        SimpleFatigueState::Fatigued
    } else {
        SimpleFatigueState::Fresh
    }
}
```

## Опциональное правило: Sanity Points (Очки Рассудка)
Мера ментальной и эмоциональной стабильности.

### Механика / Концепция
- **Базовое значение**: Начальные `Sanity Points` (SAN) равны `POW × 5`. 
- **Абсолютный максимум**: Ни при каких условиях не может превышать `99`. Специфические знания (Blasphemous Knowledge) могут снижать этот максимальный предел.
- **Потеря SAN**: При столкновении с ужасающими или неописуемыми событиями персонаж кидает `D100` против текущего значения `SAN`. При провале (а иногда и при успехе) он теряет очки рассудка.
- **Временное безумие (Temporary Insanity)**: Порог безумия (аналог Major Wound) равен **половине текущего SAN**. Если персонаж теряет такое количество очков за 5-минутный период, он впадает во временное безумие.
- **Полное безумие**: При достижении `0` SAN персонаж становится неиграбельным. Очки рассудка не восстанавливаются естественным путем.

### Архитектура Rust
```rust
pub struct Sanity {
    pub current: u16,
    pub max_cap: u16, // Обычно 99 - Cthulhu Mythos / Blasphemous Lore
    pub temp_insanity_threshold: u16, // Пересчитывается как current / 2
}

impl Sanity {
    pub fn new(pow: u8) -> Self {
        let initial_san = pow as u16 * 5;
        Self {
            current: initial_san,
            max_cap: 99,
            temp_insanity_threshold: (initial_san as f32 / 2.0).ceil() as u16,
        }
    }

    pub fn take_san_loss(&mut self, loss: u16) -> Result<bool, &'static str> {
        if self.current <= loss {
            self.current = 0;
            return Err("Character is permanently insane (0 SAN)");
        }
        self.current -= loss;
        
        let went_temporarily_insane = loss >= self.temp_insanity_threshold;
        
        // Порог пересчитывается после потери
        self.temp_insanity_threshold = (self.current as f32 / 2.0).ceil() as u16;
        
        Ok(went_temporarily_insane)
    }
}
```

## Опциональное правило: Детализация Отличительных Черт (Distinctive Features)
Развернутая механика для системы внешних отличий.

### Механика / Концепция
Количество черт определяется по таблице зависимости от характеристики `CHA` (Харизма). Чем дальше значение от `10-11` (среднего), тем больше черт. 

**Таблица зависимости от CHA:**
- `3 или меньше`: 4 черты
- `4–7`: 3 черты
- `8–9`: 2 черты
- `10–11`: 1 черта
- `12–14`: 2 черты
- `15–16`: 3 черты
- `17+`: 4 черты

Для каждой черты можно бросить `1D10` (или выбрать) категорию. Категории могут повторяться.
1. **Волосы на голове (Hair on Head)**: Лысина, косы, парик, вши, неестественный цвет, сальные.
2. **Растительность на лице (Facial Hair)**: Густая борода, сросшиеся брови, странно выбритые узоры, отсутствие бровей.
3. **Особенности лица (Facial Feature)**: Шрамы, гетерохромия, выбитые зубы, повязка на глазу, крючковатый нос, бородавки.
4. **Выражение лица (Expression)**: Презрительное, наивное, ленивое, пугающее, доброжелательное.
5. **Одежда (Clothes)**: Рваная, несоответствующая погоде, древний стиль, вульгарная, униформа, излишне украшенная.
6. **Манера держаться (Bearing)**: Неуклюжая, изящная, угрожающая, вялая, военная.
7. **Речь (Speech)**: Заикание, акцент, высокий голос, шепот, музыкальная, агрессивная.
8. **Руки (Arms and Hands)**: Шестипалость, отсутствие пальца, огромные кулаки, татуировки, разные по длине руки.
9. **Торс (Torso)**: Безволосый, горбатый, впалая грудь, бочкообразный, отсутствие пупка.
10. **Ноги (Legs and Feet)**: Хромота на одну ногу, мозоли, волосатые ступни (как у хоббитов), отсутствие пальцев.

Для низкохаризматичных персонажей (`CHA` < 10) эти черты трактуются как неприятные или пугающие. Для высокохаризматичных (`CHA` > 11) — как интригующие, впечатляющие или притягательные.

### Архитектура Rust
Для архитектуры генератора это обычные списки строк (String), которые привязываются к объекту внешности в процессе создания персонажа. Механических преимуществ не дают. Значения можно хранить в статических массивах/словарях для случайного выбора `random_choice()`.
